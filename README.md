2名（Yoshi / Oka）・2泊3日。徒歩と電車/バスで、宇治の聖地と京都市内をめぐる。
全59スポット（うち移動6件）。宿は宇治 → 祇園。

## 旅程表を見る

**→ https://sutadonman.github.io/kyoto-2026/**

スマホでそのまま開ける。Day別のカードに Google マップの埋め込み地図が付く（画面に入ったものだけ読み込む）。

### 巡礼チェック

カードのチェックを押すと、訪問済みとして記録される。Day見出しに進捗（`Day1 18/27`）が出る。
駅などの移動と宿は、進捗の分母から外している。

**記録は人ごとに持つ。** 上部で Yoshi / Oka を選ぶと、進捗とチェックは自分のぶんになり、
相手の状態は各カードに `Oka ✓` と小さく出る。別行動になっても崩れない。

**圏外でも押せる。** 宇治は徒歩移動で電波の弱い場所があるため、チェックはまず端末に保存して
画面に反映し、送信は裏で行う。失敗したぶんは未送信キューに積み、電波が戻ったときと
次回起動時に自動で送る。ツールバー右端に「未送信 3」「同期済み」などと出る。

次回起動時にシートと照合し、**端末にあってシートに無いものは送り直す**。
送信が取りこぼされていても自然に直る。相手のぶんはシートを正として取り込む。

## 立替・精算

**→ https://sutadonman.github.io/kyoto-2026/seisan.html**

誰かが先に払ったぶんを出しておくと、最後に「誰が誰にいくら渡すか」が出る。ログイン不要。

2名なので送金は常に1回。均等割で割り切れないぶんは**立替えた人の負担に寄せる**
（1001円を2人なら 501 / 500 で、501が立替えた人）。金額はすべて円の整数。

自分が出した立替だけ、フォーム下の一覧から直したり消したりできる。
持ち主の判定は `投稿者` と `ID`（自動採番）の列で行う。`ID` 列は手で編集しないこと。

## ⚠️ スプレッドシートと Apps Script は沖縄版と共用している

`sutadonman/okinawa-2026` と**同じスプレッドシート・同じウェブアプリURL・同じ TOKEN** を使う。
新規デプロイは作らない。コンテナバインドのため、スクリプトも1つを共用する。

| # | シート名 | 用途 | 旅行 |
|---|---|---|---|
| 1 | （1枚目） | スポット希望リスト | 沖縄 |
| 2 | `立替・精算` | 立替・精算 | 沖縄 |
| 3 | `巡礼チェック` | spotId / member / checkedAt | **京都** |
| 4 | `立替・精算_京都` | 立替・精算 | **京都** |

3枚目・4枚目は初回アクセス時に末尾へ自動で作られる。1〜2枚目は動かない。

旅行ごとの違いは `apps-script.gs` の `TRIPS` で切り、リクエストの `trip` で選ぶ。

```js
var MEMBERS = ['Otsu', 'Sugi', 'Runto'];   // 沖縄。書き換えない

var TRIPS = {
  okinawa: { members: MEMBERS,           expenseSheet: EXPENSE_SHEET },
  kyoto:   { members: ['Yoshi', 'Oka'],  expenseSheet: '立替・精算_京都' },
};
```

**`MEMBERS` を `['Yoshi','Oka']` に書き換えてはいけない。** 沖縄旅行は 2026.10.08–11 で
京都より後、まだ本番稼働中。書き換えると沖縄の希望リストと精算が全部 `invalid` で弾かれる。

`trip` を省略したリクエストは必ず沖縄として振る舞う。沖縄版のページは `trip` を送らないため。

### スクリプトを直したときの反映

1. スプレッドシートを開き、**拡張機能 → Apps Script**
2. [apps-script.gs](apps-script.gs) の中身で置き換えて保存
3. **デプロイ → デプロイを管理 → 鉛筆アイコン → バージョン「新バージョン」→ デプロイ**

**「新しいデプロイ」にするとURLが変わり、稼働中の沖縄版のページが動かなくなる。**

反映後は、沖縄版のフォームからも1件テスト送信して回帰がないか確認する。
権限が増えたときは再デプロイだけでは承認画面が出ず黙って失敗するので、
`appsscript.json` を更新 → `authorize` を手動実行して承認 → 新バージョン、の順で行う。

## Google マイマップに取り込む

全59スポットを1枚の地図にまとめて、2人で共有できる。

1. [kyoto-spots.csv](kyoto-spots.csv) を **Download raw file** で保存
2. [Google マイマップ](https://www.google.com/maps/d/) で新しい地図を作成
3. 左パネルの **インポート** から CSV をアップロード
4. 「目印の位置に使う列」で **検索語** を選ぶ（緯度・経度はまだ空のため）
5. 「マーカーのタイトルとして使う列」で **名前** を選択
6. スタイル分けは **日程** または **種別** の列で
7. 各自のスマホで Google マップ →「保存済み」→「マイマップ」から開ける（オフラインでも表示される）

CSV は `spots.js` から生成する。手で直さない。

```
node build-csv.mjs
```

名前の頭には `1-01` のように「日-訪問順」が付く。旅程表のカード番号と一致する。
Day2 と Day3 はどちらも東山を通るため、日を付けないと番号が地図上で重なって読めない。

UTF-8 BOM付き・CRLF なので Excel で開いても文字化けしない。
